Game 0.2.2-rc4 Prerelease2026-11-22 17:26:52 UTC

Original release and assets

Mission Humanity 0.2.2-rc4 — release candidate 4

The `release/v0.2.2` line remains hotfix-only; new features target a later release.

### Control change (**Important**)

Shift-right-click now queues orders. Ctrl-right-click confirms special interactions such as landing/deployment, merging, storage entry and tactical entry. Unmodified double-right-click remains available. These are defaults; strategic bindings can be changed in the launcher.

### Since game 0.2.2-rc3

- Queue strategic moves and attacks with Shift-right-click. Create repeating patrols with Alt-right-click and extend them with Shift+Alt-right-click, including aircraft patrols.
- Show complete selected routes and targets: green movement, red attacks, blue patrols and yellow storage rallies. Hold Shift to reveal short routes. Target display supports shared-command grouping and local appearance settings.
- Double-click selects visible own units of the same prototype; Shift adds them to the selection.
- Right-click sets a selected storage building's rally destination, including manual Exit All departures. Its optional Auto button dispatches newly produced units and units repaired to full health. Auto starts off; enabling it does not eject existing healthy occupants, begin repairs or spend resources. Shuttles have neither feature.
- Map-picker terrain, ore and landing-spot previews, with Description/Preview/Settings pages in the picker and lobby.
- Host-selected match speed: 100/125/150/175/200%, default 100%, fixed for that match.
- Launcher-managed loose-file mods, ordered resource overrides, new skirmish maps, transactional patches to existing configuration records and custom terrain. Later/lower mods win. Multiplayer checks the complete ordered content; save mod-set differences warn and load unless required resources are missing.
- Launcher-remappable strategic keys, modifiers and world mouse roles, with search, primary/alternate bindings, conflict feedback and resets. Corrected extended navigation-key handling in strategic dialogs.


### Also new since stable 0.2.1

- Interface size independent of rendering resolution, automatic display scaling and resolutions not restricted to multiples of 32.
- Optional raised limits: 500 units and buildings per player, specialist building pools up to 127 and 4000 projectiles.
- Improved sequential departures and storage boarding; steadier tactical scrolling.
- Optional campaign tech-tree unlock rechecks after loading or revisiting a planet.
- Build/research panel fixes for third and later player seats, soldier-shot desync repair and garage-exit diagonal flank guards.
- Host-selected maximum command delay: 400 ms default, with 600/800/1000 ms options.
- Recovered diagnostic faults no longer leave false crash markers.

### Launcher 0.2.2, since launcher 0.2.2-rc2

- Mods page with discovery, enable/disable, priority ordering and Apply/Revert.
- Settings → Key bindings for strategic actions, modifier/mouse roles, capture, collisions and resets.
- One shared Shift role for queueing, route reveal, repeated construction and additive selection.
- Clean settings hide Apply/Revert; edits preserve unrelated INI content.
- Configuration-language selection for localized mod patches.

### Compatibility and defaults

- Back up saves before saving with this version. New storage-policy saves are rejected by older pre-policy builds. Old native and legacy raised saves remain supported inputs; raised-limit saves require Raised limits enabled.
- Multiplayer requires the same release and identical ordered mod content, including cosmetic and shadowed files. Mods are not automatically transferred.
- Mods and bindings apply next game start; no hot reload. Invalid active mod sets fall back together to stock with a diagnostic reason. Missing required custom terrain refuses save loading before mutation; other mod-set differences warn and load.
- Improved movement, group movement and combat remain on by default. Raised limits, Tech tree fixes and each building's Auto dispatch remain off.

### Known limits

- Windows only: 32-bit game, 64-bit launcher. Eight players; no joining an already-started match; one map transfer at a time. Direct-address hosting needs port forwarding; TCP has neither relay nor host migration.
- A different second-map download in one process and same-match resync across already-applied/repeated drop/rejoin removals remain unresolved.
- Remapped held big-map keys can release on Shift and fail to reacquire on Shift-up; default Tab works.
- Raised limits retain the original fog-viewer counter limitation at 256 overlapping viewers. The selection cap remains 200 units.
- Per-unit queues hold 32 unconsumed entries including the active head. Special landing/storage/merge/tactical interactions are not ordinary queued moves. Very dense maximum-length selected routes can be expensive.
- Configuration mods edit existing records; they cannot add/remove unit or building records. No automatic mod installation or dependency solver.
- Procedural map generation and PNG/TLO authoring are source/CLI tools, not an in-game Generate button or generated campaign.
- This release does not claim to resolve every historical field crash.

### Installation

Download `mh_launcher.exe` from the launcher release, place it beside `mh.exe` and run it. You need your own copy of the game; no retail game data is included. Normal UDP relay play needs no port forwarding. The Report page sends reports only with consent. Do not run the launcher as administrator; it asks when installation needs elevation.

### Source tooling

- Procedural skirmish-map generation and custom-terrain authoring tools.
- Expanded deterministic, replay and UI checks, with owned temporary-output retention and cleanup.
- Consistent native Windows file identities across Python 3.11/3.12, preserving active-producer snapshots and strict deletion safeguards; explicit LF checkout rules for generated strategic bindings.

Game 0.2.2-rc3 Prerelease2026-10-27 23:36:41 UTC

Original release and assets

Mission Humanity / Exterminacja -- multiplayer restored, v0.2.2-rc3

The 2001 strategy game shipped with a lobby that never sent a packet. This project puts a
working multiplayer back into the retail game without replacing it: a DLL beside mh.exe
adds a lockstep turn engine and an authenticated, encrypted link, and a small launcher
keeps it installed and points it at the project's relay so players on home connections
can play with no port forwarding.

You need your own copy of the game (any retail install). Nothing from the game is in
this download.

This is a release candidate for v0.2.2. It runs with the v0.2.0-rc8 launcher or newer;
the v0.2.2-rc2 launcher is recommended (it has the new settings).

FIXED SINCE V0.2.2-RC2
- Units leaving a garage or barracks pushed the units waiting outside diagonally between
  two walls, across cliff corners, and could shut one inside a walled notch it could not
  leave. A unit now steps aside diagonally only where the way is open, and otherwise the
  exiting unit waits. This came from the original game; it is part of improved movement
  (turn that off in the launcher for the original behaviour).

FIXED SINCE V0.2.2-RC1
- The build panel of a player in the third seat or later listed wrong entries (civil and
  alien buildings, Main base, empty rows) and had no colony, power plant or mine; the
  research list was off too. Fixed for every seat, with raised limits on or off.
- A desync from soldiers' shots: where a soldier's shot started depended on what each
  player's screen had drawn, so the same shot could land differently on two machines.
  Shots now start from the same point everywhere.
- Max command delay (launcher, Multiplayer tab, host decides): 400 ms by default; 600, 800
  or 1000 ms keeps a match smooth when a player has a slow or distant connection.

WHAT IS NEW SINCE V0.2.1
- Interface size (launcher, Game tab, and in-game Options): the side panel, bottom bar,
  menus, dialogs and messages can be made bigger on a large or high-DPI screen while the
  map keeps its full detail. Auto follows the Windows display scale.
- Any game resolution, not only multiples of 32; the launcher lists the common 4:3 and
  16:9 sizes that fit your screen. "Classic sizes only" keeps the original list.
- Raised limits (launcher, off by default): up to 500 units and 500 buildings per player
  (originally 100 each); turrets, mines, laboratories, storages and production slots up to
  127 each; up to 4000 shots in flight. The host's choice applies to everyone; a save made
  with it on loads only with it on.
- Movement: a large group sent out one by one (for example from a barracks) spreads over
  open ground instead of walking in a single line.
- Movement: units boarding a shuttle one after another no longer have the door close in
  front of them.
- Tactical mode scrolls at a slower, steady speed, whatever the frame rate.
- Tech tree fixes (launcher, campaign, off by default): unlocks earned on another planet
  (for example the spaceport) are offered after loading a save or returning to a planet.
- With raised limits, a computer player that owns more buildings than the original game
  allowed no longer corrupts its own planning.
- A fault the game recovers from no longer leaves a false crash marker behind.

WHAT V0.2.1 BROUGHT (SINCE V0.2.0)
- Improved unit movement (on by default, Gameplay tab): an idle unit of yours in the way
  steps aside or trades places, two units meeting in a narrow corridor pass each other,
  and units no longer stop at corners or in side pockets.
- Group movement (on by default): a group ordered together moves at the speed of its
  slowest unit and arrives together.
- Improved combat (on by default): attack range to a building is measured to its nearest
  tile, an attacker beside its own building no longer gives up, squads can merge while
  fighting, and shots fired due south no longer show the wrong explosion.
- Turn any of the three off in the launcher for the original behaviour.
- Big map: hold Tab to see the whole map over the view. Left click or drag moves the
  camera; right click gives the selected units the same order as the side minimap.
- The minimap shows resources at every zoom, and at the widest zoom the full square map
  and the camera box.
- Single player runs on a fixed simulation step, so the game speed is the same on every
  machine; coming back from alt-tab no longer fast-forwards.
- Order voices are no longer drowned out by battle sounds, and stay after loading a save.
- Shift+click keeps the building type armed; the mouse wheel scrolls menu, info and
  side-panel lists; starting a new game after loading a save no longer reuses the save's
  settings.
- New options, off unless you turn them on: research on conquered planets (single player
  and campaign), and building without a mothership (with a separate option for the computer
  players; in multiplayer the host decides).
- Bug reports carry a snapshot of the game world, so a report can be replayed on its own,
  and a note of where the game was when it stuttered.
- Launcher: compact settings (hover a setting for its description; Compact / Detailed
  view), and if its window stops responding it records a dump that goes into the next
  report.

HOW TO PLAY
1. Download mh_launcher.exe and put it in the game folder, next to mh.exe.
2. Run it. It finds the game, downloads and installs it, and writes the relay settings for
   you. It keeps itself and the game up to date without asking, and never while the game
   runs.
3. Press Play. In the game: NETWORK GAME -> your name -> the list shows every game
   currently hosted on the relay, each with its players' ping; click one to join, or
   create your own. No IP addresses to type.
4. A match starts through the relay and goes direct between you when the network allows it
   -- either way, no router setup.

Do not run the launcher as administrator. It will ask when it actually needs to.

BUG REPORTS
- If the game stops on you, the launcher's Report tab packs that match's logs (and a crash
  dump, if there was one), shows you what is in it, and sends it only when you say so.

WHAT IS IN THE ZIP
- net             the game as shipped + multiplayer.

KNOWN LIMITS
- 8 players per game.
- One map download at a time per session.
- All players must run the same release: a v0.2.1 player cannot join a v0.2.2 game (the
  game says which version the host runs and asks to update).
- Joining a match that has already started is not possible yet.
- "Internet server" with a typed address dials that address directly and needs the host's
  port forwarded; the TCP transport ([net] transport=tcp -- UDP is the default) has no
  relay and no host migration.
- Windows only, 32-bit game process. The launcher is a 64-bit Windows program.

Everything else -- how it works, how to build it, how to host your own relay -- is in
README.md, INSTALL.md and docs/ in this repository.

Mission Humanity / Exterminacja -- multiplayer restored, v0.2.0

The 2001 strategy game shipped with a lobby that never sent a packet. This project puts a
working multiplayer back into the retail game without replacing it: a DLL beside mh.exe
adds a lockstep turn engine and an authenticated, encrypted link, and a small launcher
keeps it installed and points it at the project's relay so players on home connections
can play with no port forwarding.

You need your own copy of the game (any retail install). Nothing from the game is in
this download.

This release candidate fixes what the rc4 matches and their bug reports found.

WHAT IS FIXED
- A joiner's map download froze when entering the lobby: the game showed "can't create
  map file" for the map it had not downloaded yet and tore the lobby down. The download
  now runs to the end and the match starts.
- The host crashed when a player left and re-joined while still needing the map. A
  re-join now restarts the map transfer cleanly.
- The game crashed on an information screen whose video could not be opened. The screen
  now shows without the video.
- Four causes of the red desync warning, each one making the two machines disagree:
  - a second match in the same session carried leftovers of the first (a rematch went
    out of sync right after the start);
  - a pioneer ship landing again refilled its starting stock on the other players'
    machines only;
  - looking at your own power network in the building panel recalculated it on your
    machine only;
  - the storage panel removed destroyed units from a building on your machine only.

BUG REPORTS
- When the lobby stops responding while players are connected, the log now says so
  ("[lobby] tick STALLED ..."), with what it was waiting on.
- The desync check now also covers research state, which it could not see before.

HOW TO PLAY
1. Download mh_launcher.exe and put it in the game folder, next to mh.exe.
   (Already have an earlier version? Run your launcher; it offers this update and
   installs it -- launcher and game, one press.)
2. Run it. It finds the game, asks which configuration you want (pick "net" unless you are
   debugging), downloads and installs it, and writes the relay settings for you.
3. Press Play. In the game: NETWORK GAME -> your name -> the list shows every game
   currently hosted on the relay, each with its players' ping; click one to join, or
   create your own. No IP addresses to type.
4. A match starts through the relay and goes direct between you when the network allows it
   -- either way, no router setup.

Do not run the launcher as administrator. It will ask when it actually needs to.

If the game stops on you, the launcher's Report tab packs the logs of every match since
you started it (and a crash dump, if there was one), shows you exactly what is in it, and
sends it only when you say so. If you can reproduce a problem, reproduce it on net-debug:
its report carries the per-step hashes and the order recording.

  sides apart minutes later, where nothing points back at the click.
- A shipped configuration file could crash the game, because a comment written after a
  setting on the same line was read as part of the value. Now the comment is correctly ignored.
- Installing into Program Files now asks for administrator rights once and installs
  properly, instead of appearing to succeed while Windows quietly redirected the files
  somewhere the launcher never looks -- which also lost your logs.
- Logs are now written under %LOCALAPPDATA%\MissionHumanity\logs (one folder per game
  install) instead of the game folder, so Windows cannot redirect them somewhere the
  launcher will never find them. Your report picks them up from there.
