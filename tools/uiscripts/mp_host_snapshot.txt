# mp:X1b HOST -- capture a live world at a sim step and push it to the client over channel C.
#
# The walk is mp_host_start.txt's, unchanged, because nothing about the MENU is under test here: the
# scenario's whole assertion lives in the two peers' mh_harness.log files and is made by
# `mp_analyze.py --snapshot-verify` (the registry's post_check). What this script has to do is get a
# real 2-peer match RUNNING, on the UDP transport, and then keep it running long enough for an 8 MB
# transfer to finish at channel C's rate limit.
#
# WHY THE VERBS ARE NOT SCRIPT OPS. `[harness] snapshot_at=N` (host only, via --harness-extra-host)
# fires inside the sim-step hash block, so the blob and the per-region hashes it must reproduce are
# taken from one instant. A script op would fire on the UI driver's clock -- "when the walk reaches
# this line" -- which is a frame, not a step, and would reopen the very gap the placement closes.
#
# Pair with mp_client_snapshot.txt.

# reach the host lobby (create a game on the pre-selected map)
settled value:110
clickv 110
present Player name
settled Ok
clickl Ok
settled Create
clickl Create
present Game name
settled Ok
clickl Ok
present Available maps
settled Ok
clickl Ok

# host lobby: block until the client is really in ITS lobby, then launch
present Network players
peers 1
awaitsignal lobby
enabled Start
settled Start
clickl Start

# in-game. The capture + send fires from the harness at `snapshot_at`; this script's only job from
# here is to stay in the match. THE WAIT IS A SIM-STEP COUNT, NOT A WALL CLOCK: the transfer's cost
# is channel C's per-tick piece budget, so what has to elapse is transport ticks, and the sim step
# is the only clock both peers share that a script can read.
absent Network players
gamemode 2
# The capture is gated on the SIM, not on `absent`, for match_launch's measured reason: a peer
# entering on FLAG_START renders its first frames mid fog-of-war reveal, and at headless frame rates
# that stage is frame-rate dependent. 6000 is past saturation and is the number every other in-game
# capture in the suite uses, so both peers pin the same sim moment.
gameclock 6000
capture s1_host_ingame
log HOST in a live UDP match; the harness captures + sends the world at [harness] snapshot_at
# THE TERMINAL WAIT IS `stalled 35000`, and the reason is measured (mp:X3a, 2026-09-29). Before X3a
# this was `gameclock 75000`, which the host reached before the import landed, so nothing ever asked
# the importing peer to survive anything. Moving it to `gameclock 110000` deadlocked: the client's
# `snapshot_hold` freezes its sim, so it stops advancing its lockstep horizon, and the HOST -- lockstep-
# blocked on it -- stops at the client's frozen horizon (last_horizon_ms=24680, gclk=24650 in the
# measured run), so during the hold it cannot advance its game clock. Then the GS2 data timeout (15 s)
# dropped the "silent" client, the host won, and its gameover ended the client's match 15 s after the
# import -- the `gameclock` wait was only satisfied later, by a match that was already over.
# So the host does NOT own a running clock while a peer is held. What it does own is the STALL: it
# is lockstep-blocked on the held client from the moment of the import, and `stalled <ms>` is true
# while that block has lasted >= <ms>. 35 s of stall = the client has held its imported world for at
# least ~35 s of wall time (the registry raises `data_timeout_ms` to 120000 so the host does not drop
# it meanwhile), and only then does the host release the client's rendezvous. If the import never
# happens the host never stalls and the scenario times out -- the correct failure.
# The registry post_check asserts the consequence (`mp_analyze --hold-survival-ms 30000`).
stalled 35000
log HOST reached the end-of-transfer window
# mp:X3 step one. Under `[harness] snapshot_hold` the importing peer FREEZES its sim the moment the
# blob lands, so every `gameclock` wait on THAT side would block forever. The host RELEASES the client
# with a rendezvous, which is the one wait the held peer can still satisfy.
signal held
log HOST released the client
end
