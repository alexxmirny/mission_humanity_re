# mp:U44 HOST -- a lockstep stall must neither close the player's open building dialog (short stall) nor
# let the "Player not responding" kick modal share the screen with it (long stall).
#
# Retail bug (llm_net_lockstep_overlay_dismiss 0x004c7d1c / sync_overlay_show 0x004c7eea): the dismiss forces
# GAME_MODE=2 whenever the widget list is empty -- and the building dialog runs with an EMPTY list in mode 3 --
# so recovery from ANY stall closed the dialog, without clearing _G_LLM_UI_ACTIVE_DIALOG; the kick modal's
# arm guard accepted mode 3 with an empty list, so it armed over the dialog, which kept its clicks (the modal's
# buttons were unclickable) and returned at every later stall. Fix: libmh overlay_hoist.cpp (ledger of what
# lockstep itself armed + a stash of the displaced dialog), `[net] overlay_dialog_guard` (default 1).
#
# THE STALLS ARE FORCED, NOT WAITED FOR: the registry row's shim triggers `blackhole c2s` on this script's
# `log HOST dlg_stall: <phase> start` lines and lift it on `... end` (client -> host dropped, so the HOST's sim
# parks at the horizon). `stalled <ms>` proves each stall was really in force for that long.
#
# THE DIALOG is the selected building's status dialog (the red X in the HUD panel's icon column, the same
# opener mp_host_canceltask.txt uses). An idle mother offers Sell / Close -- NEVER click Sell here.
# Pair with mp_client_dialog_stall.txt.

clickl Create
present Game name
settled Ok
clickl Ok
present Available maps
settled Ok

settled Start

absent Network players

# land the mother (shift+right-click deploy), select it, open its status dialog
rclick 480 330 shift
gameclock 20000
simclick 500 330
gameclock 20200
simclick 882 271
retry 1500 3 3 gamemode 3
gameclock 20600
screensettled
dump
capture dialog_open

# (a) SHORT stall: below the kick-modal threshold. The retail dismiss closed the dialog on recovery; now it must
# survive, still be the active screen (mode 3), and still be clickable (verified at the end of (b)).
log HOST dlg_stall: short start
stalled 800
log HOST dlg_stall: short end
gameclock 24000
# bounded: the retail rule has closed the dialog by now, and an unbounded wait here costs the negative arm
# the runner's whole walk watchdog. `retry` rewinds the gameclock step once, then ABORTs.
retry 3000 1 1 gamemode 3
present Ok
capture after_short

# (b) LONG stall: past the threshold, but short of the ~10 s of data silence after which the game drops the
# peer ("kicked-off"): `stalled` counts from the moment the sim parks, which is ~4.4 s after the blackhole
# starts (the lookahead), and the modal appears at ~6 s of silence, so 3500 sits in the window [6 s, 10 s). The kick modal shows (its three buttons are the proof it owns the screen)
# and the dialog is stashed, not drawn under it nor holding its clicks.
log HOST dlg_stall: long start
stalled 3500
present Reset counter
present Disconnect player
absent Ok
capture modal
# the modal's own buttons are LIVE: `hovered` is the game's own hit test (llm_ui_widget_input_tick), which the
# retail stale ACTIVE_DIALOG pre-empted. (Not clicked: every kick-modal button ends in a player removal.)
hovered Reset counter
hovered Disconnect player
log HOST dlg_stall: long end
# afterwards the player's dialog is RESTORED (mode 3, its widgets live), the modal is gone
absent Reset counter
gamemode 3
present Ok
gameclock 40000
capture after_long
# restored and clickable: Ok closes it cleanly (mode 2, no dialog widget list left active)
clickl Ok
gamemode 2
absent Ok
capture dialog_closed

# (c) a second LONG stall with NO dialog open: the retail stale ACTIVE_DIALOG would come back here. Only the
# modal may be on screen, and after it nothing but the map.
log HOST dlg_stall: long2 start
stalled 3500
dump
capture modal2
present Reset counter
absent Ok
hovered Reset counter
log HOST dlg_stall: long2 end
absent Reset counter
gamemode 2
absent Ok
gameclock 60000
capture after_long2
signal hostdone
end
