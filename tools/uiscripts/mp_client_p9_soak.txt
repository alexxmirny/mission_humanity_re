# ends the run. Shared by the three P9 rows (resync_storm_repro / resync_gate_proof /

# This is the joiner: `[net] lockstep_step_ms=60` (the row's net_extra_client, G267) -- the field's

# WHY THIS SCRIPT ENDS RIGHT AFTER ITS CAPTURE (mp:P9 2/2, 2026-09-22). It used to wait for the
# same `present Continue game` dialog the host waits for, and in the storming configuration it
# never got there: the blackhole lands INSIDE a barrier ~97 % of the time (a 2.0 s barrier every
# 2.07 s), and a RECEIVER that has entered the mode-8 barrier leaves it only on the leader's RESUME
# frame (dispatch inner 0xe) -- the wait-screen frame runs nothing but dispatch, so no time_tick,
# no GS2 data timeout, no graceful_drop, no presents even (the client's mh_frametime.log stops
# dead at the last BEGIN), and the below-quorum dialog can never come. The runner keeps a
# COMPLETE'd peer's game ALIVE until every peer has finished, so ending here keeps this peer in
# the match for the whole soak (its `[resync]` lines run to the blackhole) and lets the host's
# dialog end the run. The wedge itself is a stock bug worth its own row (tracker mp:P9 progress
# names it), not something this script should paper over with a predicate.
