# D15 -- the POSITIVE case for the exit witness (D15, net_diag.cpp).
#
# NOT a suite scenario, and it cannot become one: it ends by making the game QUIT, so the run has no
# COMPLETE status and no capture to compare -- ui_test reports it as PROCESS-GONE, which is the point.
# It is a probe, kept because an instrument that has only been proven to ARM is not proven to FIRE,
# and this whole item exists because of diagnostics that looked fine and said nothing.
#
# What it proves, in one run and on a death whose cause we already know:
#   * `; EXIT llm_wnd_on_destroy caller=0x... mode=2 ...` reaches mh_net.log BEFORE the process goes.
#   * the runner prints `[crash] 0 -- a CLEAN exit ...`, i.e. the retained-handle exit code works and
#     names the right class -- the game chose to stop, nothing killed it, nothing faulted.
#
# It is also a rehearsal of the cause-#2 incident shape: a peer that stops mid-script with no WER
# report. Compare what this run prints against the 2026-08-06 record, where all four hosts produced
# "never became ready" and nothing else.
#
# The walk to a live game is menu_walk's, verbatim; only the tail differs. `&Quit game` is value 113
# in the ESC menu list (dumped 2026-08-27: Options 111, Diplomacy 100, Quit game 113, Return 103).

# that is itself the finding: the click missed, or Quit no longer leads to WM_DESTROY.
