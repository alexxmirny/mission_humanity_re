#
# WHAT THIS SHAPE HAS TO PRODUCE, and why no 2-peer walk can (dead-ends G300). The carrier
# (mp:U19i) splices the `call llm_net_send_lockstep_kick` at 0x0049c330 in the ORIGINAL
# llm_net_lockstep_dispatch. That call runs only when ALL of these hold on one peer:
#   (a) a datagram arrives from a sender whose roster slot is already flagged AI (written off),
#   (b) this peer is the leader for it (llm_net_lockstep_is_local_leader_peer: the first
#       ALIVE|HUMAN slot other than the sender is OURS -- slot 0, the host, here),
#   (c) the dispatch loop is still running, i.e. this peer is still in session mode 3.
# A 2-peer removal breaks (c): the frame that flags the peer also ends the survivor's match. So
# this is a THREE-peer match, and the written-off peer is one whose SIM is fenced while its
# transport stays up (mp:GS2's shape, measured 3-peer on 2026-09-21): the other two drop it after
# [net] data_timeout_ms of horizon silence and play on (count_active_players == 2), while its
# horizon-heartbeat thread keeps sending 9-byte type-0x02 adverts. The first one to reach the
# host after the host's own removal satisfies (a)-(c).
#
# WHAT EACH ARM THEN DOES. Guarded (the ship default): the thunk snapshots the datagram across the
# kick, logs `; [net] gone-peer frame guard FIRED #1: ...`, and the advert parses as the advert it
# was -- this peer keeps playing. Unguarded (`gone_peer_frame_guard=0`): the kick's six bytes
# overwrite the head of the 9-byte advert, the parse lands on a mantissa byte at offset 6 as an
# outer tag, and the default arm raises outcome 7 (NETWORK_ERROR) -- this peer's match ends, and
# the `absent Continue game` below never resolves. tools/check_gone_peer_guard.py reads which.
#
# TOPOLOGY: the DET3 one (host on rig VM A, the other survivor on rig VM B, the FENCED peer as the
