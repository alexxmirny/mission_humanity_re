# res_walk -- ONE process walks the resolution / HUD / panel-row / zoom segments that used to be 25 separate rows.
# Everything runs on the committed saves 2-almost.sav (a campaign save on Aman: a 64 x 64 map, 8 available and 13
# owned buildings, a selected landed building and two insect groups beside the wrap seam) and ayy30.sav (21 available
# buildings, 74 units in groups of 5 / 18 / 51, for the lists that need more than 2-almost holds). Both are deployed
# into the lane; the Load dialog lists them newest-first and 2-almost is the top, preselected row, so a plain
# `clickl Load game` loads it, and ayy30 (the second row) is picked with the split-click pattern.
#
# Each segment starts with `mark <old row name>`: the line goes into mh_video.log, mh_input.log and mh_net.log, and every
# post_check slices the logs on it (tools/walk_segments.py). A capture is named <old row>__<name>, so a red frame
# names the row it replaced. The size is changed IN GAME (ESC > Options > Screen size > Ok), as a player does; the
# options dialog is centred, so its spinner sits at (W/2-22, H/2-3) of the CURRENT rendered size and one click is the
# next list entry, wrapping (res_walk.ini: [0] 640x480 [1] 800x576 [2] 1024x768 [3] 1280x768 [4] 1280x960
# [5] 1280x1024 [6] 1920x1080 (1056 rendered) [7] 1920x1440 [8] 2048x1152 [9] 2560x1440):
#   1024x768 (490,381)  1280x768 (618,381)  1280x960 (618,477)  1280x1024 (618,509)  1920x1056 (938,525)
#   1920x1440 (938,717)  2048x1152 (1002,573)  2560x1440 (1258,717)  640x480 (298,237)
# The Load dialog is centred on the map area, so its second row sits at ((W-160)/2-10, H/2-95).
