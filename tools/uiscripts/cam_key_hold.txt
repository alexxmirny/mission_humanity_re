# mp:SES3c -- the KEYBOARD camera-scroll _HELD latches have no scenario: `key` is a down+up pair,
# so a held arrow key (scancode 0x4b LEFT, matching _G_LLM_CAM_SCROLL_LEFT_HELD) is not
# expressible with it. `keyhold` fixes that (an unpaired DOWN held for N presents, then an UP), and
# this scenario proves CAM_SCROLL_LEFT_HELD tracks it: set while the key is down, camera scrolling
# the whole time, cleared on release. Sibling of cam_edge_scroll.txt (the MOUSE-edge half of the
# same eight latches); this is the KEYBOARD-held half.
#
# SHARES cam_edge_scroll's LANE (tools/test_ui.py `share_lanes`) rather than growing the capture
# suite's registry -- tools/lane_alloc.py's block is at its ceiling (81/81; see its own header).
# Same reasoning as GX1's gx1_overlay_residue sharing debug_overlay's lane: same main-menu framing,
# never scheduled concurrently with it.
#
# THE ASSERTION IS THE post_check, NOT THE PIXELS -- same shape as cam_edge_scroll. s0_menu is a
# boot-sanity frame taken before the walk; every claim this scenario makes lives in
# tools/check_cam_trace.py's `--expect-held` reading the `; [mtrace]` line's held= column.
#
# Single-peer, same menu walk as cam_edge_scroll.txt: seat an AI in slot 1 and Start alone.

settled value:110
capture s0_menu
clickv 110
present Player name
settled Ok
clickl Ok
settled Create
clickl Create
present Game name
settled Ok
clickl Ok
present Available maps
settled Ok
clickl Ok

# host lobby: OPEN -> AI on slot 1, gated on the "Computer" name label (the per-slot spinner
# rebuilds the widget list, and a click mid-rebuild misses) -- same as cam_edge_scroll.txt.
present Network players
settled Start
click 70 132
present Computer
enabled Start
clickl Start

# In-game. Centre the cursor and LEAVE it there for the whole run: this scenario is about the
# KEYBOARD held-latch column, not the mouse edge-scroll cam_edge_scroll.txt already covers, and a
# cursor sitting at a screen edge would latch CAM_EDGE_* too and muddy the held= column this checks.
absent Network players
gamemode 2
cursor 320 240
gameclock 2000

# 1. CONTROL: no key held, all eight latches clear, camera still.
cursorhold 320 240 60

# 2. HOLD LEFT (scancode 0x4b) for 600 presents. CAM_SCROLL_LEFT_HELD latches on the DOWN event
#    and stays latched with no paired UP -- the unpaired hold `keyhold` exists to express -- and
#    the camera scrolls left the whole time (frame count matched to cam_edge_scroll's own proven
#    600-present hold, since both need >= 3 [mtrace] samples at the 500 ms camera heartbeat).
keyhold 0x4b 600

# 3. RELEASED. The UP event `keyhold` sends on its last present clears the latch -- the fall half
#    check_cam_trace's --expect-held requires, same as --expect-rise-fall does for the mouse edge.
cursorhold 320 240 120

log cam_key_hold: held scancode 0x4b (LEFT) for 600 presents, then released -- read the held= column
end
