# res_drag_wide (RES13) -- a drag-select wider than half the map, on screen
# The game orders a drag by the SHORTER arc between the anchor and the cursor (outline AND the selection walk), which is the
# on-screen order only while the two are less than half a map apart: always at a retail size (<= 864 px against 1024), not at
# 1920x1056 on the 64-tile map. mh.dll's drag_dir_fix orders by the screen when both ends are on screen.
# Camera at world 1440,1696 (as res_drag_box), so a screen point is world = camera + screen (mod 2048).
#   d9_wide_tlbr   anchor (100,300) -> cursor (1500,700): 1400 px wide, anchor left. Must select what the screen box holds
#                  (both insect groups, ids 2 and 5, are in x 600..800), outline 100,300..1500,700.
#   d10_wide_brtl  the reverse drag (anchor (1500,700) -> cursor (100,300)): the same box, the same ids.
#   (No vertical analogue: the map pane at 1920x1056 is shorter than half the 2048 px map, so a drag taller than 1024 px cannot be
#   made on screen; the row arithmetic is covered by res_list_selftest `drag dir`.)
# tools/check_drag_box.py --wide asserts all of it; the fix-off twin ([video] drag_dir_fix=0) draws and selects the complement arc.
