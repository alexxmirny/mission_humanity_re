# G270 (measured 2026-09-22, real rig runs; the finding is inlined here): the scenario originally expected
# a real transport death to leave the retail "Connection to server lost" wording (outcome=7) in
# place, on the theory that U19d's discriminator needed its negative arm exercised. MEASURED: outcome
# 7 has exactly ONE producer in the whole closure -- the unknown-outer-tag/garbled-frame arm
# (libmh/lockstep/rx_dispatch.cpp's handle_garbled) -- which a clean transport death never reaches.
# Both a graceful quit (U17a) and a real transport death (U17b/fast-drop) retire through
# llm_strat_player_presence_lost, which calls the outcome dialog with outcome=8 ("you are the last
# player !") UNCONDITIONALLY, regardless of how the peer left. U19e's `gone_peer_frame_guard`
# (default ON) fixed the one known way a clean departure used to misroute into outcome 7 (a
# stale-buffer race in the re-broadcast), so in this build outcome 7 is not reachable from a normal
# departure at all -- there is no live case where "Connection to server lost" is the correct wording,
# and U19d's correction (gated on outcome==7) is consequently dead code here too. So this scenario's
# real, provable claim is narrower: a transport death is retired through the SAME fast in-order
# broadcast (fast-drop) a graceful quit uses, not the framing-bug arm and not the old below-quorum
# silence-timeout stall -- confirmed by the log-based post_check (tools/check_transport_death.py).
#
# THE KILL: paired with a `[net] transport=tcp` link routed through `tools/net_shim.py` (this test's
# `shim`/`shim_timeline`), which schedules a `cut` (real FIN close) well after both peers are
# in-game. A `blackhole` (silent drop, socket stays OPEN) was tried FIRST and measured to NOT trigger
# the fast-drop route at all -- net_transport.cpp's MH_Net_TakeDeadPeer()/g_dead_peer is armed only
# by a real socket close (recv()==0/error), which a blackholed connection never produces; that run
# instead fell out through a separate below-quorum/presence-loss detector with no fast-drop line
# (also outcome=8). `cut` is the primitive that actually exercises U17(b).
#

# proof here is the WIDGET state: `present Continue game` (the end-of-match dialog's own button,
# reached ONLY through the lockstep dispatch's below-quorum path) plus the log-based post_check.
