04

The one architectural cause

All of it — the fps-capped sim, the frame-time tail, and the freeze cliff — traces to a single fact: the lockstep horizon is advertised once per rendered frame (llm_strat_time_tick → llm_net_send_lockstep_extend). So a render hitch on either peer becomes a netcode stall, and the sim clock advances only as fast as the slowest peer renders. Input latency therefore has a hard floor of one sim tick = 100 ms (the sim is fixed at 0.1 s — the movement/production constants are hardcoded per-tick, so the tick can't be made finer without changing game speed), and on a render-hitchy peer the practical floor is whatever buffer covers its worst hitch.

The fix (scoped in tasks/mp-perf-decouple.md): advertise the horizon on a fixed real-time cadence independent of the render loop, so a render hitch no longer starves the peer. Same change fixes the fps-capped sim. Determinism (proven this session) is preserved — only the wall-clock pacing of advertisement changes, never the sim content.
